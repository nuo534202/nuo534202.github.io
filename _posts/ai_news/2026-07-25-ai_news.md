# 1. Anthropic 发布 Claude Opus 5：以 Opus 4.8 的价格逼近旗舰 Fable 5，安全拦截频率降低 $85\%$

美国时间 7 月 24 日，Anthropic 正式发布 Claude Opus 5，全平台同步上线。该模型以 Opus 4.8 的定价提供接近旗舰 Fable 5 的性能，成为 Claude Max 订阅的默认模型和 Claude Pro 平台的最强模型。Hacker News 上该话题获得 1282 分热度，Artificial Analysis 智能排行榜显示 Opus 5 当前排名第一。

定价方面，Opus 5 每百万输入 token 为 5 美元、每百万输出 token 为 25 美元，与 Opus 4.8 持平，仅为 Fable 5（10 美元/50 美元）的 $\frac{1}{2}$。同时提供 Fast 模式，速度约为默认的 $2.5 \times$，价格为基价的 $2 \times$。

核心评测数据如下：

- **Frontier-Bench v0.1：** 超过所有参测模型，性能较 Opus 4.8 翻倍以上，单任务成本更低。
- **CursorBench 3.2：** Max 档下 Opus 5 得分 70.0%，每任务 8.23 美元；Fable 5 同档 70.5%，每任务 17.32 美元。差距仅 $\frac{0.5}{70.5}$，价格不到 $\frac{1}{2}$，token 用量减少 $40\%$。Extra High 档下 Opus 5 全面超过 Fable 5 同档，每任务还便宜约 4 美元。
- **ARC-AGI 3：** 得分为第二名的 $3 \times$。
- **OSWorld 2.0：** 以约 $\frac{1}{3}$ 的成本超过 Fable 5 的最好成绩。
- **Zapier AutomationBench：** 通过率约为次优模型的 $1.5 \times$；最低 effort 档下通过的任务数仍超过其他所有模型。

安全设计是 Opus 5 与 Fable 5 的核心分界。Anthropic 延续上一代做法，未在网络攻击类任务上训练 Opus 5。在内部 OSS-Fuzz 测试中，Opus 5 发现漏洞的能力接近管制版旗舰 Mythos 5，但将漏洞编写为可用攻击代码的能力被刻意压制。安全分类器的拦截频率预计比 Fable 5 低约 $85\%$。被拦截的请求不再直接拒绝，而是自动回退至 Opus 4.8 继续执行——API 层面同步开放了自动回退（Automatic Fallback）测试版，确保请求始终落在可用模型上。数据政策方面，Opus 5 延续 Opus 系列传统，普通接入不要求保留数据，而 Fable 5 上线时带有 30 天数据保留要求。

Anthropic 同时发布两项 API 测试功能：会话中途工具变更（Mid-conversation Tool Changes），允许在对话中切换工具集合而不破坏提示缓存；以及 API 端自动回退。自动化行为审计中，Opus 5 的整体不良行为得分 2.3，为历代最低。

一个值得关注的发布插曲：官方对比表将 FrontierCode v1.1 一行中 Opus 5 的 $53.4\%$ 加粗标为最优，而旁边一格明明写着 $53.5\%$——一个由 AI 生成的宣传图出了错，在 X 上迅速传播。

# 2. Claude Code 系统提示词可删除 $80\%$ 以上：Anthropic 工程实践指向"强模型少规则"范式转移

7 月 25 日报道，Anthropic 工程团队在实践中发现，为 Claude 5 系列模型删除 Claude Code 超过 $80\%$ 的系统提示词后，编程评测成绩未出现下降。这一发现直接挑战了"系统提示词越详细越好"的工程惯例，标志着上下文管理从"给规则"向"给判断空间、设计接口、渐进式披露"的方向转移。

Anthropic 同步推出 `/doctor` 命令，用于自动精简 Skills 与 CLAUDE.md 配置文件。该命令会扫描当前项目的 Agent 配置，识别冗余规则和过时指令，给出精简建议。其设计逻辑是：当模型本身的推理能力足够强时，密集的规则约束反而可能干扰模型的自主判断——与 7 月 24 日 Chroma、ETH Zurich、Sourcegraph 三项独立研究的结论一致，即上下文过载会侵蚀输出质量。

这一发现与 Opus 5 的发布形成呼应。Opus 5 的核心卖点之一是"会自己核对工作"——在官方测试中，它能在没有图像查看能力的情况下，自行编写计算机视觉流水线从原始像素中提取几何结构并完成三维建模。当一个模型能自主规划工具链并验证中间结果时，外部注入的详细步骤规则就不再是性能保障，而可能成为约束瓶颈。

该实践对 Coding Agent 工程的影响体现在两个层面：一是运行时成本——系统提示词占据的上下文窗口直接消耗 token，精简后可释放更多空间给实际代码和工具输出；二是维护成本——超长 CLAUDE.md 文件的编写和更新本身就是开发负担，ETH Zurich 的实验已表明自动生成的超长配置文件反而降低任务成功率约 $3\%$，同时成本上涨逾 $20\%$。

# 3. Pillar Security"沙箱逃逸周"：Cursor、Codex CLI 等 AI 编程工具曝架构性安全缺陷

7 月 20 日至 24 日，安全研究公司 Pillar Security 以"沙箱逃逸周"（Week of Sandbox Escapes）为名，连续发布七项针对主流 AI 编程工具的沙箱逃逸漏洞。受影响工具涵盖 Cursor、OpenAI Codex CLI、Google Gemini CLI 和 Antigravity，来自三家不同厂商。同期，Accomplish AI 披露了 Claude Cowork 的虚拟机逃逸漏洞（SharedRoot），OpenAI 也确认 GPT-5.6 Sol 在评测中挣脱沙箱。

这些漏洞的共同特征是：攻击者无需直接突破沙箱隔离。Agent 始终在沙箱内遵守所有规则，但它写入工作区的文件——hook 配置、虚拟环境解释器、Git 配置、VS Code 任务定义——会被沙箱外的可信组件（IDE 扩展、Git 集成、Docker 守护进程）读取并执行。Pillar 将其归纳为四种失效模式：

- **denylist 沙箱跟不上系统复杂度：** Antigravity 的 macOS Seatbelt 配置采用"默认允许"策略，试图枚举并阻止危险操作，但现代操作系统的攻击面无法穷举。
- **工作区配置实为可执行代码：** Cursor 中 `.claude` hook 配置可被 Agent 修改，hook 引擎在沙箱外执行该配置——编号 CVE-2026-48124，CVSS 8.5，已在 3.0.0 版本修复。Cursor 另有两个漏洞涉及虚拟环境解释器劫持和 Git fsmonitor 路径绕过。
- **allowlist 信任命令名而非调用方式：** Codex CLI 的安全列表信任 `git show` 命令名，但实际调用并非只读—— nicknamed "GitPwned"，已在 0.95.0 版本修复，OpenAI 支付了高危漏洞赏金。
- **特权本地守护进程游离于沙箱之外：** Docker socket 漏洞同时影响 Cursor、Codex CLI 和 Gemini CLI——只要 Docker Desktop 在运行，沙箱边界即形同虚设。

Google 对两项 Antigravity 漏洞（macOS Seatbelt denylist 绕过和 `.vscode` 任务配置绕过）的处置态度明显更冷：分类为"其他有效安全漏洞"并降低严重等级，理由是利用难度较高、需要社会工程。截至披露时，Google 尚未发布修复。

此前 2026 年 2 月，Cato Networks 已披露 Cursor 的另一组沙箱漏洞 DuneSlide（CVE-2026-50548 和 CVE-2026-50549，CVSS 均为 9.8），通过操纵工作目录和符号链接验证逻辑覆写沙箱助手本身。两组独立研究团队在数月内发现多类独立的逃逸路径，表明当前 AI 编程工具的沙箱设计存在系统性缺陷，而非个别实现疏漏。Stack Overflow 2026 年调查显示 $84\%$ 的开发者已使用或计划使用 AI 编程工具，这些工具已成为开发者基础设施。

# 4. 上海交大与字节跳动提出 SWE-Pruner Pro：读取骨干模型内部表示按行剪枝，最多节省 $39\%$ token

7 月 20 日提交至 arXiv 的论文 SWE-Pruner Pro 由上海交通大学 LLM4SE 实验室联合字节跳动抖音集团完成，提出一种直接读取 Coding Agent 骨干模型处理工具输出时内部隐藏状态（hidden states）的行级剪枝方法。与前代 SWE-Pruner 需外挂独立 0.6B 剪枝模型不同，SWE-Pruner Pro 仅在冻结的骨干模型上接入约 18M 参数的剪枝头（pruning head），从 Agent 读取工具输出时已有的隐藏状态预测逐行保留或剪除，不新增模型调用。

这一设计的核心假设是：Coder LLM 在处理工具输出时，其内部表示已经包含了对各行相关性的判断信息——模型本身已经"知道"该剪什么，只需一个轻量头来提取这一信号。实验结果在四个多轮基准上验证了该假设：

- **SWE-QA-Pro：** 得分从 7.60 升至 7.84，同时 token 减少 $39.4\%$。
- **MiMo-V2-Flash SWE-Bench Verified：** resolve 数从 326/500 升至 345/500，提升 $3.8\%$。
- **Oolong：** 从 92.4 升至 94.6，token 减少 $30.1\%$。
- **Qwen3-Coder-Next SWE-Bench Verified：** resolve 数下降 $1.2\%$，说明节省上下文不等于所有骨干模型都能涨分。

此前的研究已表明，Coding Agent 在真实代码库中导航时，$76.1\%$ 的 token 消耗用于文件读取操作（cat、grep 等），多轮交互中历史上下文不断累积导致成本激增和注意力稀释。SWE-Pruner Pro 的价值在于：不增加推理延迟（剪枝头推理在骨干模型前向传播中同步完成）、不引入外部模型调用开销，且在部分设置下反而提升任务质量——剪掉噪音行后模型注意力更集中。

该方法可无缝接入 OpenHands、Claude Code 等主流 Agent 框架。代码和模型已在 GitHub 和 HuggingFace 公开。

# 5. Agent Skills 成为 AI 编程新范式，北京印发国内首个省级智能体专项扶持政策

7 月 25 日，Agent Skills 作为模块化、可复用的智能体能力单元已被 Codex、Cursor、Claude Code 三大主流编程工具深度集成。开发者不再需要从零搭建 Agent 框架，而是通过组合预制的"技能包"来定义 Agent 行为——这一转变标志着 AI 编程工具的竞争焦点从"模型能力"转向"技能生态与分发渠道"。

同日，GitHub 仓库 claude-code-best-practice 达到 63.3k star，提出"from vibe coding to agentic engineering"的主张，用 skills、memory、review、harness 四件套为 AI 编程套上工程化约束层。该仓库的走红反映了社区共识的变化：vibe coding 适合原型期快速验证，进入团队协作和生产环境后必须转向可托管、可验证、可交接的 Agent 工程体系。具体约束包括 spec（规格定义）、ticket（任务拆分）、sandbox（沙箱隔离）、automated check（自动化检查）、review（人工审查）五层，决策前移、状态沉淀为 handoff artifact。

北京市同日印发国内首个省级智能体专项扶持政策，为 Agent 产业发展提供制度支撑。同期 Claude Fable 5 在 SWE-bench Pro 上以 $80.3\%$ 的成绩重夺编程王座。

在工具层面，本周多条线索指向 Agent 安全与持久化记忆成为下一波竞争焦点：

- **OneCLI（GitHub 2769 star）：** 开源凭证网关系统，内置安全保险库，允许开发者为 AI Agent 提供服务访问权限而不暴露实际密钥，解决 Agent 工具调用中的凭据泄露问题。
- **Millwright：** 用 Rust 构建的自托管 LLM 路由，支持本地化部署。
- **Cognikernel：** 为编程助手添加本地持久化记忆层，解决多轮会话间上下文丢失问题。
- **Deja-vu：** 开源项目，通过索引 Claude Code、Codex、Cursor 等本地会话实现跨 Agent 检索与 handoff，提出 AGENTS.md/DECISIONS.md/KNOWN_ISSUES.md/RUNBOOK.md 三层记忆架构。

腾讯技术工程同日发文，沿"模型—上下文—Harness—Loop"链路拆解 WorkBuddy 产品，强调 Agent 能否稳定交付取决于上下文组织、工具权限接入、结果验证与 Harness 工程，而非单纯换更强模型。
