# 1. Anthropic 与 AMD 达成战略合作：Claude 一个周末完成 ROCm 全适配，CUDA 护城河遭遇 AI 反向冲击

7 月 22 日，在 AMD Advancing AI 大会上，AMD 与 Anthropic 宣布达成战略合作。AMD 承诺向 Anthropic 进行最高 50 亿美元的战略股权投资，Anthropic 将在 AMD Helios 机架级解决方案中部署最高 2 吉瓦的 Instinct MI450 系列 GPU（首批 1 吉瓦于 2027 上半年交付），搭配 EPYC Venice CPU、Pensando 网络和 ROCm 软件栈。这是 AMD 首次直接投资 Anthropic，也首次官方确认 Anthropic 已在使用当前代 MI355X GPU。

比订单规模更具冲击力的是 Anthropic 联合创始人兼首席计算官 Tom Brown 在大会上披露的适配过程。团队原本预期在新硬件上启动模型会是"一个大项目"，但实际体验完全不同：一名工程师让 Claude 执行 AMD Instinct MI355 与 ROCm 平台的适配任务后，让流程在周末自行运转，周一便拿到了 Anthropic 领先模型在该硬件上"周末期间持续攀升"的性能曲线。整个过程仅涉及一名工程师和一台 AMD 提供的机架。AMD 官方账号随后转发了包含 Brown 表态的推文，并确认将在工程团队中广泛采用 Claude 优化 ROCm 开发。

分析师 Austin Lyons 随即评论称"我们已过了 CUDA 护城河时代"。这一判断的逻辑基础是：英伟达 CUDA 生态壁垒的本质不是技术的不可替代性，而是迁移的"人力成本壁垒"——即使竞争对手硬件性能追平，企业仍需投入大量工程师重新适配软件栈。当 Claude 能在一个周末内完成整套适配流程时，硬件采购决策将更多取决于性能、价格和供应可得性，而非生态锁定。SemiAnalysis 最新分析指出，Anthropic 推理基础设施毛利率已从 $38\%$ 跃升至逾 $70\%$，并在第二季度实现营业利润盈利。

Anthropic 此前的算力供应商已包括英伟达 GPU、亚马逊 Trainium 芯片（Project Rainier，10 年超 1000 亿美元 AWS 支出）、谷歌 TPU（2027 年起 3.5 吉瓦）以及从 SpaceX Colossus 1 数据中心租用的 300 兆瓦英伟达算力。AMD 成为第六个独立算力来源。两天内 AMD 市值增加约 850 亿美元，总市值突破 9080 亿美元。

# 2. DeepSeek V4 旧版 API 今日截止：deepseek-chat 与 deepseek-reasoner 正式退役，开发者面临"静默降级"陷阱

7 月 24 日 15:59 UTC，DeepSeek 正式停用 deepseek-chat 和 deepseek-reasoner 两个旧版 API 模型名。此后任何使用这两个名称的请求将直接返回错误，无宽限期、无自动转发。这一截止日期由 DeepSeek 在 4 月 24 日 V4 预览版发布时设定，经过三个月兼容窗口后于今日到期。

迁移本身只需修改模型字符串：deepseek-chat 对应 deepseek-v4-flash（非思考模式），deepseek-reasoner 对应 deepseek-v4-flash（思考模式）。但关键的陷阱在于 deepseek-reasoner 的映射目标——许多开发者习惯将其用于高强度推理任务，而该别名实际指向 284B 总参数（13B 激活）的 Flash 模型，而非 1.6 万亿总参数（49B 激活）的 Pro 模型。直接重命名到 deepseek-v4-flash 会让依赖深度推理的工作负载静默降级，需要显式指定 deepseek-v4-pro 才能获得更高推理质量。

V4 同时引入了架构层面的变化：推理模式从模型名移入请求体参数。旧体系下选择 deepseek-reasoner 即获得链式推理，V4 统一为单一模型配合 `{"thinking": {"type": "enabled"}}` 开关，支持 low / medium / high / xhigh / max 五档 reasoning_effort 调节。两个行为变化需要特别注意：思考模式下 temperature、top_p 等采样参数被忽略（保留兼容但不生效）；链式推理内容返回在独立的 reasoning_content 字段中，工具调用场景必须在后续请求中回传该字段，否则返回 400 错误。

V4 两款模型的定价差异显著：V4-Pro 为 $1.74$ 美元/百万输入 token、$3.48$ 美元/百万输出 token；V4-Flash 为 $0.14$ 美元/百万输入、$0.28$ 美元/百万输出。作为对比，GPT-5.6 Sol 定价为 $5$ 美元/$30$ 美元。V4-Flash 的输出 token 单价约为 Sol 的 $\frac{1}{107}$。两款模型均默认支持 100 万 token 上下文，V4-Pro 在最大上下文下的推理计算量约为 V3.2 的 $27\%$，KV 缓存仅约 $10\%$。V4 还首次引入峰谷计费：高峰时段（9:00-12:00、14:00-18:00）价格为平峰的 $2 \times$。在 Codeforces 上 V4-Pro 评级 3206（约人类排名 23），SWE-bench Verified 开源权重版本达 $80.6\%$。

# 3. Anthropic 托管智能体平台（CMA）六项重大更新：单会话技能上限从 20 飙至 500

7 月 22 日，Anthropic 在托管智能体平台（Claude Managed Agents, CMA）上一口气推出六项更新，距离 Cowork 桌面端"录制技能"功能发布仅一天。六项更新的核心内容如下：

- **技能上限从 20 拉到 500：** CMA 的 Skills 是给 Agent 注入专业指令的知识包，此前单会话上限仅 20 个。以金融客服 Agent 为例，覆盖开户、KYC、反洗钱、投诉处理、合规免责、多语言切换就需七八个技能，叠加地区监管差异和 A/B 测试版本即撞天花板。500 个技能位由同一会话中的所有 Agent 共享，运行在统一托管沙盒中，Agent 之间共享内存和环境变量，由协调器统一调度。技能机制采用渐进式加载（progressive disclosure）三层按需加载系统，将 50 个技能的上下文占用从约 15 万 token 压缩至约 2000 token。
- **思考力度五档调速：** effort 参数此前在 API 层面已有，但 CMA 中的 Agent 不能单独设置——整个会话统一跑默认档位。现在可直接写入每个 Agent 的模型配置，五档可选：low / medium / high / xhigh / max。同一会话中，分流协调器可用 low 省成本，产品答疑用 medium，投诉升级用 high，法律合规用 max。
- **种子会话一步创建：** 此前需先 POST 空壳会话再逐条塞初始事件，高并发场景冷启动慢。现在 POST /v1/sessions 可直接携带最多 50 条 initial_events，会话创建即进入 running 状态。
- **子 Agent 实时流下探到线程级：** 6 月底 CMA 上线会话级 event_deltas，但子 Agent 仍是黑盒。本次更新支持订阅子 Agent 的独立线程流，实时查看其思考和输出进度。
- **7 种新 webhook：** 补齐 4 种环境事件和 3 种记忆存储事件，至此 CMA 全生命周期（环境搭建、Agent 部署、运行状态、记忆管理）均可事件驱动对接外部系统。
- **Agent 更新版本字段变可选：** 单流程场景可省略 version 字段，跳过并发控制的 409 错误处理。

这三方竞争格局正在形成：OpenAI 押注入口（将聊天、编程、自主工作塞入 ChatGPT 超级应用），Google 押注基础设施（GCP + TPU + 协议标准），Anthropic 押注 OS 级深度（托管沙盒 + 全栈 Agent 控制 + 思考力度调速）。

# 4. Coding Agent 失效根因不是模型而是上下文：多项研究共识指向"上下文工程"

7 月社区研究综合指出，大多数 Coding Agent 在真实代码仓库中失效的根因并非模型能力不足，而是上下文供给方式错误。三项独立研究从不同角度得出一致结论：

- **Chroma 的 18 模型"上下文腐烂"实验：** 向量数据库公司 Chroma 对 GPT-4.1、Claude Opus 4、Gemini 2.5 Pro、Qwen3-235B 等 18 个前沿模型进行长上下文测试，发现所有模型均随输入长度增加而性能下降，无一例外。传统的"大海捞针"（NIAH）基准因仅测试词汇匹配而高估了模型能力——一旦引入语义模糊性或干扰项，性能在上下文超过 $50\%$ 容量后急剧衰减。一个反直觉的发现是：模型在句子被打乱、缺乏逻辑结构的文本中表现反而优于逻辑连贯的文档，这暗示注意力机制在处理结构化输入时可能受到负面影响。2026 年跟进数据显示，Claude 3.5 Sonnet 在 LongSWE-Bench 上的准确率从 32K 上下文的 $29\%$ 跌至 256K 的 $3\%$。
- **ETH Zurich 的 CLAUDE.md 实验：** 研究发现自动生成超长 CLAUDE.md 文件反而降低 Agent 任务成功率约 $3\%$，同时成本上涨逾 $20\%$。向 Agent 灌入更多上下文说明并不等于让它做得更好——信息过载直接侵蚀输出质量。
- **Sourcegraph 的 CodeScaleBench：** 该基准测试表明，为 Agent 提供正确的工具组合比提供更长的上下文窗口更关键。工具调用的精准匹配对代码任务成功率的贡献，显著高于单纯扩大上下文窗口。

三项研究的共同指向是"上下文工程"（Context Engineering）——主动管理和精简输入内容，而非简单地将所有信息塞给模型。实践策略包括摘要（让 Agent 定期将历史行动提炼为更短的记忆）和检索（将知识存储在向量数据库中，每步只检索最相关片段）。对 Coding Agent 而言，这意味着 Agent 在搜索、探索和回溯过程中积累的噪音，会直接降低后续每一步的输出质量——模型足够聪明，前提是上下文保持干净。

# 5. 腾讯云发布 CodeBuddy NPC：云端智能体直接交付成果，首轮 Token 消耗降超 $90\%$

7 月 23 日，腾讯云正式发布云端智能体 CodeBuddy NPC，依托 CNB 研发平台运行。开发者只需派发一个任务，CodeBuddy NPC 即可自主完成方案规划、代码开发、提交 PR、执行测试，并根据 CI 结果持续修改，直到交付可验收的成果。官方称首轮 Token 消耗从 2 万以上降至约 2000，降幅超过 $90\%$。

CodeBuddy NPC 的设计思路与其他 Coding Agent 工具存在差异。多数现有工具（如 Claude Code、Codex CLI）以本地终端为核心运行环境，开发者需要在自己的开发环境中配置模型和工具链。CodeBuddy NPC 将整个执行流程迁移到云端 CNB 平台，开发者通过任务派发而非逐步指令进行交互，支持多 NPC 按角色组队协作。该产品已集成至 CNB 平台，无需改造现有工具链。

同期国产 AI 编程工具链出现集体开源趋势：阿里 Qwen 团队开源 Qwen Code 命令行工具（深度适配 Qwen3-Coder、支持离线私有化部署、可批量重构百万行代码库）；开源项目 Orca（MIT 许可，27k Star）以 Git Worktree 隔离为核心，并排运行 Codex、Claude Code、OpenCode 等 Agent 于独立分支，统一跟踪 Diff 与任务状态；GitHub 工具 CC Switch 以跨平台桌面应用统一管理 Claude Code、Codex、Gemini CLI 等多 Agent 的 API Key 与模型映射。钛媒体分析指出，SWE-bench Verified 头部模型的分差已不足 3 个百分点，但成本差距接近 $24 \times$，竞争焦点从"模型军备"转向"分发渠道与数据闭环"。
