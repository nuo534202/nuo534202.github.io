# 1. Kimi K3 开源权重今日发布：2.8T 参数模型开放下载，幻觉率却攀升至约 $51\%$

7 月 27 日，月之暗面（Moonshot AI）在 HuggingFace 和 GitHub 上发布 Kimi K3 的完整模型权重，采用 Modified MIT 许可证。K3 是首个进入 $3$ 万亿参数级别的开源模型，总参数量 $2.8$ 万亿，采用稀疏混合专家架构（Stable LatentMoE），内置 $896$ 个专家，每个 token 仅激活 $16$ 个，活跃参数约 $50$B。权重采用 MXFP4 量化（训练感知量化，非后训练量化），完整权重存储约 $1.4$TB，最低部署门槛约为 $8$ 节点 $\times 8 \times 80$GB GPU。

K3 的两项架构创新值得关注。Kimi Delta Attention（KDA）是一种混合线性注意力机制，在 $100$ 万 token 上下文下解码速度比标准注意力快 $6.3 \times$；Attention Residuals（AttnRes）允许各层从任意早期层选择性提取表示，在 MoE 架构中不同专家激活于不同深度时尤为关键。Moonshot 声称 AttnRes 使训练效率提升约 $25\%$，额外计算开销不到 $2\%$——这两项数据均为厂商自报，尚无独立第三方复现。

在 Frontend Code Arena 盲测排行榜上，K3 以 $1679$ Elo 排名第一，领先 Claude Fable 5（$1631$）和 GPT-5.6 Sol（$1618$）。托管 API 定价为每百万输入 token $3$ 美元、每百万输出 token $15$ 美元，缓存输入 $0.30$ 美元。Moonshot 的 Mooncake 推理基础设施在编程负载上缓存命中率超过 $90\%$，实际每任务成本约 $0.94$ 美元，约为 Opus 4.8（$1.80$ 美元）的 $\frac{1}{2}$。

但独立评测机构 Artificial Analysis 发现了一个 Moonshot 未在发布材料中披露的数据：K3 的幻觉率从前代 K2 的 $39\%$ 升至约 $51\%$。该机构将幻觉率定义为错误答案除以所有非正确响应——作为参照，Claude Fable 5 在同一基准上的幻觉率为 $54.9\%$。K3 的问题不在于绝对水平，而在于趋势：模型在变得更强的同时，也更不清楚自己什么时候是错的。这一取舍对代码生成（K3 登顶的领域）影响有限，但对事实敏感的知识型任务构成实际风险。K3 在 SWE Marathon 和 Program Bench 上领先所有模型，但在整体性能上仍落后 Fable 5 和 GPT-5.6 Sol——Moonshot 自己也承认这一点。

自部署的法律层面同样需要审视。Moonshot 是北京注册实体，中国《国家情报法》第七条要求所有组织和公民支持、协助和配合国家情报工作，《数据安全法》和《网络安全法》赋予政府数据检查权。自托管 K3 在自有基础设施上推理不经过 Moonshot API，但公司的法律义务不因服务器物理位置而转移。Modified MIT 许可证的具体条款尚未随权重同步发布，商业使用前需确认许可条件。

# 2. MCP 2026-07-28 无状态规范明日冻结：AI 编程工具协议迎最大修订，会话机制彻底移除

7 月 28 日，Model Context Protocol（MCP）2026-07-28 规范将正式发布最终版。这是该协议自推出以来最大规模的修订，发布候选版于 5 月 21 日锁定，经过 $10$ 周验证窗口后定稿。核心变化是协议层从有状态转为无状态——移除 `Mcp-Session-Id` 头和 `initialize` / `initialized` 握手流程。

旧规范（2025-11-25）下，客户端调用工具前必须先发送 `initialize` 请求建立会话，服务器返回的 `Mcp-Session-Id` 将客户端绑定到特定服务器实例，水平扩展需要粘性路由和共享会话存储。新规范下，协议版本、客户端信息和能力信息改为放入每个请求的 `_meta` 字段，新增 `server/discover` 方法供客户端按需获取服务器能力。每个请求自包含，可被任意服务器实例处理——远程 MCP 服务器从此可直接运行在普通轮询负载均衡器后面，无需深度包检测。

配套的基础设施改进包括：

- **可路由：** 新增 `Mcp-Method` 和 `Mcp-Name` 必需头，负载均衡器和网关无需解析 JSON-RPC 体即可路由请求。服务器拒绝头与体不一致的请求。
- **可缓存：** `tools/list` 和资源响应携带 `ttlMs` 和 `cacheScope` 字段，基于 HTTP `Cache-Control` 语义，客户端知道响应在多久内有效及是否可跨用户共享。
- **可追踪：** W3C Trace Context 通过 `_meta` 中的固定键名传播，开箱即用兼容 OpenTelemetry 分布式追踪。
- **多轮请求：** 服务器需要用户输入时返回 `InputRequiredResult`（含 `requestState`），客户端收集答案后携带 `inputResponses` 重新发起调用——重试可落在完全不同的服务器实例上继续执行。

两个扩展从实验性核心特性升级为正式扩展框架：MCP Apps 允许服务器渲染交互式 HTML 界面（沙箱 iframe 内运行），Tasks 扩展支持长时间运行的异步工作。认证方面强制迁移至 OAuth 2.1。

Akamai 安全研究团队的分析指出，旧版本中协议级会话劫持、未请求的服务器提示、弱认证三类风险被消除，但新的攻击面随之产生：应用自管理的状态、富交互式 AI 界面、异步任务流均需开发者自行构建安全边界。协议不再管理状态，但应用程序仍然可以有状态——服务器通过工具返回标识符（如 `basket_id`），模型在后续调用中将其作为参数传回，这种"显式句柄"模式使状态对模型可见而非隐藏在传输元数据中。正式规范附带 $12$ 个月旧功能弃用窗口。

# 3. 三星与微软斥巨资投资 Mistral AI：欧洲"主权 AI"获芯片与云双线加持

据英国《金融时报》7 月 22 日报道，三星电子正在与法国 AI 初创公司 Mistral AI 进行高级别投资谈判，拟注资约 $10$ 亿欧元。此轮融资若完成，Mistral 的估值将从上一轮的 $120$ 亿欧元跃升至约 $200$ 亿欧元（约 $228$ 亿美元）。三星此前已通过风险投资部门对 Mistral 进行过投资，本轮属于战略加码。瑞典投资者 EQT 旗下的 Scaleup Europe Fund、Novo Holdings 和 Santander 也在洽谈参与。

三星的投资逻辑不只是财务布局。作为全球最大的存储芯片制造商，三星需要为 HBM（高带宽内存）和逻辑芯片锁定长期大客户——在 AI 芯片短缺的背景下，通过资本纽带绑定 AI 模型公司已成为行业惯例。此前美光已投资 Anthropic 并签署长期存储供应协议，AMD 也宣布向 Anthropic 投资最高 $50$ 亿美元。对 Mistral 而言，三星的加入意味着关键芯片供应的保障。

同一周，微软宣布与 Mistral 扩大合作关系，作出"数十亿美元级别"的算力基础设施投入承诺。Mistral 将部署数千块英伟达最新 Vera Rubin GPU 扩充欧洲算力，微软则借助这些算力服务自身的 AI 开发和云业务。Mistral 最新模型 Mistral Medium 3.5 和 Mistral OCR 4 将集成至 Microsoft Foundry，Medium 3.5 还将支持 Copilot Studio 企业版。微软 Azure 客户可直接使用 Mistral 位于法国的数据中心开发 AI 应用。

Mistral 的基础设施扩张轨迹清晰：$3$ 月通过首次债务融资筹集 $8.3$ 亿美元，用于在巴黎附近建设配备 $13800$ 块英伟达 GB300 GPU 的数据中心；另在瑞典承诺 $14$ 亿美元数字基础设施投资，目标到 $2027$ 年底在欧洲达成 $200$MW 算力容量。CEO Arthur Mensch 向《金融时报》透露，公司年度经常性收入有望在 $2026$ 年底突破 $10$ 亿美元。

Mistral 的投资热度与地缘政治背景直接相关。美国政府此前限制外国使用 Anthropic 最新 Mythos 和 Fable 模型，欧洲各国和企业对减少对美国技术栈的依赖产生急迫需求。Mistral 成立于 $2023$ 年，专注于可定制、可私有化部署的开源模型，已向法国军队供应 AI 技术，定位为美国主导 AI 开发商和云提供商的欧洲替代方案。但"主权 AI"并非技术自给自足——Mistral 数据中心使用英伟达芯片，微软扩展云分发，ASML 提供半导体制造设备，三星可能加入内存芯片专长。核心不在于完全自主，而在于对 AI 模型在哪里开发、部署和运营拥有更大控制权。

# 4. Google 开源 Always-On Memory Agent：用 LLM 持续整合替代向量数据库，记忆写入 SQLite

Google 高级 AI 产品经理 Shubham Saboo 本周在 Google Cloud Platform 官方 GitHub 仓库开源了 Always-On Memory Agent 项目，采用 MIT 许可证，允许商业使用。该项目基于 Google Agent Development Kit（ADK）和 Gemini 3.1 Flash-Lite 构建，提出了一个与当前主流 RAG 架构相反的记忆方案：不用向量数据库，不用 embedding，只用一个 LLM 持续读取、思考和写入结构化记忆到 SQLite。

架构采用编排器模式（orchestrator pattern），内含三个专家子 Agent：

- **IngestAgent：** 接收文件或文本输入，利用 Gemini 的多模态能力提取结构化摘要、命名实体、主题和重要性评分，将结果作为新记忆记录写入 SQLite。支持 $27$ 种文件格式，涵盖文本、图片、音频、视频和 PDF。
- **ConsolidateAgent：** 按可配置计时器运行（默认每 $30$ 分钟），审查所有尚未被关联的记忆，寻找跨领域连接，从模式中生成新洞察，并压缩相关信息——模拟人脑睡眠时的记忆整合周期。生成的洞察本身成为一等记忆记录，构建不断增长的关联知识网络。
- **QueryAgent：** 处理用户查询，读取所有存储的记忆和整合洞察，合成带来源引用的结构化答案，每条答案可追溯到具体记忆记录。

Gemini 3.1 Flash-Lite 的选择有明确的经济逻辑。该模型定价为每百万输入 token $0.25$ 美元、每百万输出 token $1.50$ 美元，首 token 延迟比 Gemini 2.5 Flash 快 $2.5 \times$，输出速度提升 $45\%$。一个 $24$ 小时运行的记忆层每 $30$ 分钟执行一次整合周期，token 消耗持续累积——只有足够便宜的模型才能让"always on"在经济上可行。

该项目本质上是一个参考实现而非即装即用的产品。它不提供租户隔离、业务系统连接、审核流程、细粒度保留策略或审计访问控制。企业架构师已在 X 上提出治理疑虑：当记忆不再受会话约束时，谁有权写入记忆？什么内容被合并？保留策略如何设定？Agent 在后台"做梦"并交叉授粉记忆而没有确定性边界时，可能成为合规噩梦。移除向量数据库并不移除检索设计——复杂度的位置变了，但复杂度本身没有消失。对于有界记忆的单租户 Agent（个人助手、单一客户历史支持机器人），轻量栈可能足够；大规模部署可能仍需更严格的检索控制和显式索引策略。

# 5. OpenAI 为 Codex 上线实时语音与 Appshots：编程 Agent 脱离键盘，可读取活动窗口画面

OpenAI 为 ChatGPT 桌面端的 Codex 编程 Agent 上线基于 GPT-Live 的实时语音功能。开发者戴上耳机即可用声音指挥多个 Agent——查看进度、修改需求、引导多 Agent 工作流，全程无需触碰键盘。语音对话支持自然打断，开发者可以随时插入修正或追问。

与语音同步推出的还有 Appshots 功能：Codex 可直接读取当前活动窗口的画面内容和文字，无需手动截图。终端弹出报错或界面元素异常时，Codex 能"看到"并直接提供修复方案。这一设计将编程 Agent 的输入模式从"用户描述问题"扩展为"Agent 自行感知环境"。

Andrej Karpathy 对此评论称，语音输入在复杂任务中具有独特优势——它允许开发者以低认知成本一次性倒出完整上下文，包括任务背景、约束条件和当前状态，而文字输入往往导致信息碎片化。他的判断是，vibe coding 正在从"用自然语言写代码"演进为"把完整想法和屏幕画面直接交给 Agent"。

同周，OpenAI 全量开放了 ChatGPT Health 功能，允许美国 $18$ 岁以上用户接入 Apple Health、Epic 电子病历、One Medical 和 Function Health 数据，在聊天中通过 `@Health` 调用健康信息做纵向对比和就诊准备。OpenAI 为此斥资 $1$ 亿美元收购医疗数据公司 Torch。但该功能上线前一天，佛罗里达州前牧师 Scott Winters 对 OpenAI 和 CEO Sam Altman 提起诉讼——称 ChatGPT-4o 将其头晕和血压波动症状判定为"不危险"，建议"躺在躺椅上休息"，导致肺栓塞治疗延误六周。原告要求法院在 ChatGPT Health 继续运营前下令进行独立安全审计。

Codex 语音功能的上线背景是 OpenAI 近期稳定性问题持续发酵。7 月 $25$ 日 API、ChatGPT、Codex 三线同时宕机 $111$ 分钟，连续 $17$ 天无完全正常日。编程 Agent 任务动辄运行数十分钟，服务中断发生在任务中间意味着整个工作可能作废。语音操控让开发者可以在中断发生时更快介入，但根本问题仍是基础设施可靠性。
